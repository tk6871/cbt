# v5.9.3 원본 표시 복원·코드 로딩 최적화

## 범위

- 사용자 정정에 따라 문제·해설 이미지 경량화는 원복했다. 추가 변환을 하지 않는다.
- `QuestionCard.vue`에서 문제/인쇄 해설의 srcset을 제거했다. 확대뿐 아니라 풀이 화면도 기존 업스케일링 원본을 사용한다. 답안 좌표·원문·정답·해설·저장 형식은 변경하지 않았다.
- 문제용 사본382개(32,339,052바이트)를 배포 폴더에서 Git 제외 작업 폴더 `work/responsive-images-unused/`로 옮겼다. 원본은 처음부터 변경하지 않았다. 사본은 복구 가능하다.
- 테마용28개 사본만 유지하며 생성 도구와 런타임도 테마 경로만 허용한다.

## 구현

- `useStudyGuideData.ts`: 필답형·자료실 은행을 첫 메뉴 진입 때 로딩한다. 메뉴 노출은 작은 키 목록으로 유지한다. 자료 다운로드 실패를 다른 화면으로 전파하지 않는다.
- 진행 중인 실전 세션이 있으면 홈에서도 자료를 준비한다. 자료가 도착하기 전 ID를 빈 문제은행과 비교해 지우지 않는다. 기존 답안/시각/필터를 복원한다.
- 실패한 ES 모듈 요청을 브라우저가 기억하는 경우를 확인했다. 사용자가 다시 불러오기를 누르면 기존 pagehide 저장 및 방문 화면 복원을 거쳐 새로고침한다.
- 필답형 타이머는 자료 로딩 완료·진행 중일 때만 실행하고 종료/대기 중에는 해제한다.
- `pluginExperiences.ts`로 안내 데이터를 분리했다. 거대한 App 전체를 재작성했다는 의미는 아니다.
- 문제은행 준비 결과를 WeakMap에 재사용한다. 교재 은행이 뒤늦게 도착하거나 원본 은행 객체가 교체되면 다시 준비한다.
- 이전 읽기 폭 제한, 화면 안 카드 모션, 프레임당 보기 측정, 테마 배경 URL 보정은 유지한다.

## 측정과 저장소 조사

- 메인 청크: 이전1,853,227바이트(gzip397,821) → 1,259,019바이트(gzip275,366), gzip 약30.8% 감소. 필답 자료538,851바이트(gzip116,034)는 필요 시 별도로 로딩한다.
- 전체 사이트 속도가31% 빨라졌다는 의미가 아니다. 데이터 은행·폰트·기기 성능·네트워크는 별도다. 처음 자료실을 열 때는 인터넷 연결이 필요하다.
- `node tools/audit-deployment-footprint.mjs`: 미사용 생성 사본0, 이전 버전 청크0. 소스/작업 도구/원본/PDF를 임의로 삭제하지 않는다.
- assets 약539MB, data 약59MB, modern 약22MB다. Git 이력은 유지하므로 과거 커밋에 들어간 사본 용량이 Git 전체에서 즉시 사라지지 않는다. 강제 푸시/이력 재작성은 하지 않았다.

## 검증

- typecheck, production build, PWA593 검사 통과.
- 최종 PC 브라우저15검사20.4초 통과. 작성 답안·실전 타이머 복원, 자료 지연 로딩·실패 복구, 은행 캐시 무효화 및 아래 이미지 검사를 포함한다. 수정 전 실패한 검사와 이전 버전 결과를 현재 통과로 세지 않는다.
- 원본382장 해시, 기존140/154 대표문항·과거179ID, 이미지 답안 선택·취소·다크/라이트·이어서풀기 검사 포함.
- 실물 기기 발열/FPS, Safari, 실제 배포 업데이트, APK 빌드는 미실행이다. 이번 작업은 기존 Vue UI를 유지한 작은 버전 최적화다.

## 인계

- 새 도구 설치·다운로드·OCR·업스케일링 없음. 기존 Node/Chrome 도구로 재현한다.
- 원본 문제 이미지 경량화는 사용자의 새 지시 전까지 보류한다. 프레임워크 교체 및 Git 이력 재작성도 하지 않는다.
- 로컬 커밋 후 GitHub Desktop에서 Push origin. 다음 장치는 Pull 후 작업하고 동시 편집하지 않는다.
