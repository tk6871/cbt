# 한도와 별개로 실행하는 필답형 검증

이미 설치된 Node/npm/Chrome과 프로젝트 의존성을 사용합니다. AI 요청·새 설치·다운로드·이미지 자동 교체·커밋·Push는 하지 않습니다.

저장소 터미널에서 실행:

실시간 진행 화면은 `node tools/practical-log-viewer.mjs --background`로 열고
브라우저에서 `http://127.0.0.1:4192/`에 접속합니다. 2초마다 최신 실행의 상태와 로그가 갱신됩니다.
단계 선택·최신 줄 따라가기·연결 끊김 후 재시도를 지원합니다. 검사가 끝나도 결과를 볼 수 있습니다.
이 로그 서버는 Mac 로컬에서만 열리며 검증 작업을 새로 시작하지 않습니다.

검증 작업 실행:

```sh
node tools/run-practical-verification.mjs --background --build
```

- 이미지 검수 기록/해시 → 문제 구조 → 타입 → 웹/Android 웹 번들 빌드 → PWA → PC 브라우저 순회 순서입니다. 이미지 파일 자체 교정 작업이므로 모바일·태블릿 반복 검사는 하지 않습니다.
- `--build`를 빼면 현재 빌드의 검증만 합니다. `--plan`은 실행 목록만 출력합니다.
- 자동 검증은 이미지 로딩·배치·연결을 확인합니다. 사진 속 가림·잘림·정답 노출, 원문/정답의 사실 확인은 별도의 직접 검토가 필요합니다.
- 실행하면 PID와 결과 폴더가 출력됩니다. 해당 폴더의 `status.json`에서 단계별 상태, `각단계.log`에서 상세 결과를 볼 수 있습니다. 마지막 상태가 `passed`여야 자동 검증 전체 통과입니다.
- 실패하면 다음 단계는 실행하지 않습니다. 재실행 시 새 결과 폴더를 만들고 처음부터 검사합니다.
- 별도 로컬 서버를 자동으로 열고 작업 종료 후 닫습니다. 기존 미리보기 서버에는 영향을 주지 않습니다.
- 실행 중 소스/데이터를 편집하거나 별도 빌드를 동시에 실행하지 마세요. 이 스크립트끼리는 잠금으로 중복 실행을 차단합니다.
- 중지하려면 출력된 PID를 확인해 `kill -TERM 숫자PID`를 실행하세요. 강제 종료/재부팅으로 `active.lock`이 남았다면 그 안의 PID가 실제로 종료됐는지 확인한 뒤 해당 잠금 파일만 지워야 합니다.
- AI 한도가 끝나도 이미 시작한 로컬 프로세스는 독립적으로 진행할 수 있지만, Mac 종료·절전·앱의 프로세스 정리까지 버티는 보장은 없습니다. Mac을 켜 두세요. 새 판단이나 추가 권한 승인은 자동으로 발생하지 않습니다.
- 빌드는 배포 파일을 갱신하지만 서명 APK를 만들거나 사이트에 업로드하지는 않습니다. 기존 문제 원본은 바꾸지 않습니다.
